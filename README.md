# Автотранс-Логистика — генератор XML для Контур.Логистики

Рабочее веб-приложение для создания черновика `ON_ZAKZVGO` версии 5.01 из двух PDF:
**поручение экспедитору** и **договор-заявка перевозчика**.

## Использование
1. Загрузить оба PDF и нажать «Распознать документы».
2. Проверить извлечённые поля. Можно менять любые значения.
3. Нажать «Скачать XML» и загрузить файл в Контур.Логистику.
4. Проверить результат импорта и **подписывать только после проверки**.

## Локально
```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```
Затем открыть http://127.0.0.1:8000.

## Из любого компьютера
Залейте каталог в **приватный** GitHub-репозиторий и создайте Render Web Service с этим репозиторием. `render.yaml` включён. После деплоя сервис доступен по HTTPS-адресу Render с любого компьютера. На Render в корне репозитория должны лежать `main.py`, `requirements.txt`, `templates/`, `static/`.

> **Важно про отсутствие пароля:** любой человек, знающий публичный адрес, сможет пользоваться генератором. Поэтому сервис не сохраняет PDF, реквизиты заявок, водителей и перевозчиков в базе. Файлы обрабатываются в оперативной памяти, возвращается только XML. Для архива, истории и справочника перевозчиков нужен вход по аккаунту; не включайте их на открытом сайте. Пароль можно добавить позже. Не загружайте PDF с паспортами/данными водителей на неизвестный сервер.

## Ограничения
- Текстовые PDF, до 15 МБ и 50 страниц каждый. Для отсканированных PDF потребуется OCR (не входит в MVP).
- Поддерживаются знакомые форматы поручений и договоров-заявок, но другие шаблоны могут распознаваться частично.
- Для отсутствующих данных (включая ЭДО-идентификатор перевозчика, метод определения массы, реквизиты владельца склада, габариты) XML не выдумывает значения. Проверяйте их в Контуре при импорте.
- Дата/время из окна готовности груза могут отличаться от согласованного времени подачи.
- Контур может менять требования к формату. Импорт проверялся пользователем на одном образце, но это не гарантия приёма каждого последующего XML.
- Указан код вида тары `00` как в ранее импортированном образце; перепроверьте тип упаковки перед отправкой.
- Дата создания XML — текущая дата сервера в Europe/Moscow, дата заявки — дата поручения.
- Нет подключения к аккаунту Контура и автоматической отправки, только файл для ручного импорта.

## Безопасность
Сервис не требует пароля, не сохраняет PDF и не ведёт архив, ограничивает размер и число запросов, устанавливает HTTP no-cache. Деплой должен быть доступен только через HTTPS. При коммерческом использовании рекомендуются контроль доступа и стандартное веб-ограничение по IP / WAF на хостинге.

## Раздел «ЭТРН из заявки»

Откройте `/etrn`. Для безопасного дополнения титула 1 ЭТрН нужен **исходный XML `ON_TRNACLGROT` v5.01 из Контура**, а также два текстовых PDF: поручение экспедитору и договор-заявка перевозчика.

- Существующие непустые атрибуты и тексты XML всегда защищены. Редактировать можно только заранее разрешённые пустые поля.
- Данные из PDF — только подсказки для пустых полей; при расхождении значение исходного XML остаётся без изменений.
- Незаполненные фактические даты, ИНН грузополучателя, тип организации и ГАР/ФИАС не придумываются.
- XML-патч не меняет черновик в Контуре напрямую. При импорте в редактор он может создать новую накладную или перезаписать поля. **Обязательно проведите пробный импорт на отдельном черновике и сверьте исходные реквизиты.**
- Исходный файл в браузере не модифицируется и не сохраняется на сервере.
